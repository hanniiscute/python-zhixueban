## 一、项目简介

「python智学伴」是面向 Python 初学者的**个性化学习辅导 Web 应用**。针对传统网课「一刀切」、答疑反馈慢、刷题缺乏针对性三大痛点，系统基于讯飞星火大模型构建了 Multi-Agent 协同架构：

- **1 个编排器**（Orchestrator）负责意图识别与智能体路由
- **10 个专项智能体类**，其中 5 个承担核心教学职责（画像分析、内容生成、测验出题、学习辅导、路径规划），另有思维导图、阅读答疑、代码问答、学习评估等能力智能体
- **1 套 RAG 检索增强**保证 AI 回答不离纲（自建课程知识库，15 个核心知识点 + 206 道习题 + 55 条学习路径）
- **1 份动态学习画像**贯穿全流程，让每一次交互都反哺下一次教学

作品完整实现了对话学习、学习画像、学习路径、练习测验、错题复习、学习报告六大功能模块，PC 与手机端自适应，已部署在线可访问。

## 二、解决什么问题

| 痛点 | 传统方案的问题 | 本作品的解法 |
|---|---|---|
| **进度一刀切** | 网课所有人看同一份视频，「会的反复听、不会的没人讲」 | 画像分析智能体维护学习者画像，路径规划智能体据此定制并动态调整学习路线 |
| **答疑反馈慢** | 遇到报错只能翻搜索引擎，答案质量参差 | 学习辅导智能体引导式答疑，代码报错先让学生自己猜哪行有问题 |
| **刷题不针对性** | 刷题软件只判对错，不讲错在哪、下一步补什么 | 测验出题智能体按当前水平出题；错题自动入本、更新画像、触发复习节点 |
| **学完就忘** | 练习结果不回流，下次仍然从零开始 | 错题驱动全链路协同：一次练习触发五个智能体接力工作 |

**政策导向**：教育部等九部门《关于加快推进教育数字化的意见》明确提出「探索智能学伴，实现人工智能驱动的大规模因材施教」；国家教育数字化战略行动 2.0 将「智能化」列为核心方向。本作品正是这一方向在高校编程学习场景的落地实践。

## 三、核心功能

| 模块 | 功能说明 |
|---|---|
| **对话学习** | SSE 流式对话，支持 Markdown 渲染、代码高亮；三阶段思考状态可视化（分析画像 → 检索知识库 → 生成内容） |
| **学习画像** | 雷达图展示水平、兴趣、易错点等多维度画像，由交互行为自动增量更新 |
| **学习路径** | 分阶段学习路线，每个阶段带进度条与完成计数；练习通过后自动解锁下一阶段 |
| **练习测验** | 按画像难度生成题目，支持单选/多选/代码题；作答后即时判定并给出解析 |
| **错题复习** | 错题自动入库并按错误次数排序；支持单题 AI 精讲（讲清「你错在哪」）与「已掌握」移除 |
| **学习报告** | 汇总学习时长、完成主题、正确率、连续天数等数据，由大模型生成阶段性学习分析 |
| **快捷指令** | 输入框上方一键提示词：规划路径 / 出 5 道题 / 生活例子讲解 / 分析基础 / 小测验 |
| **辅助能力** | 思维导图生成、讲义阅读答疑、代码报错诊断、学习评估 —— 由对应能力智能体承接 |

## 四、系统架构

### 4.1 分层架构

```
┌─────────────────────────────────────────────────────────┐
│  前端展示层    Vue 3 + Vite —— SPA，SSE 流式渲染          │
├─────────────────────────────────────────────────────────┤
│  后端服务层    FastAPI + Uvicorn —— RESTful + SSE 推送    │
├─────────────────────────────────────────────────────────┤
│  智能体层      编排器（意图识别 + 路由）                  │
│                核心教学：画像分析 · 内容生成 · 测验出题   │
│                         学习辅导 · 路径规划              │
│                辅助能力：思维导图 · 阅读答疑 · 代码诊断   │
│                         学习评估                         │
├─────────────────────────────────────────────────────────┤
│  数据与模型层  MySQL（画像/路径/错题） · FAISS（知识库）  │
│                星火大模型（理解与生成）                   │
└─────────────────────────────────────────────────────────┘
```

### 4.2 请求处理链路

```
用户消息
  → POST /api/chat/stream (SSE)
  → Orchestrator 意图识别
       ① 强关键词匹配（规则命中即返回）
       ② Embedding 语义相似度（向量检索）
       ③ 弱关键词兜底
       ④ 默认路由到学习辅导
  → 分发到对应智能体（注入学习者画像 + RAG 检索片段）
  → 流式输出 + 生成资源卡片 + 自动更新画像
  → SSE 事件序列：thinking → content → [resource_*] → [profile] → done
```

### 4.3 多智能体协同闭环

```
做错练习题
   ↓ 测验出题智能体上报错题
错题收入错题本（wrong_questions 表，同题重复做错累加次数）
   ↓ 画像分析智能体
画像更新「易错主题」字段（error_patterns）
   ↓ 路径规划智能体
学习路径自动插入复习节点
   ↓ 内容生成智能体
下次讲解针对性加强该知识点
   ↺ 循环往复 —— 学得越多，AI 越懂这个学生
```

> 设计取舍：**为什么不用一个大模型身兼五职？** 一个 prompt 同时当老师、出题人、规划师会互相干扰 —— 出题的忘了照顾水平，规划的忘了错题。拆成多个专精提示词，共享同一份画像数据，既能各司其职，又不会出现「人格分裂」。

## 五、AI 技术方案

### 5.1 大模型集成

- **模型**：讯飞星火 4.0Ultra（OpenAI 兼容 HTTP 接口），支持流式（SSE）与同步调用两种模式
- **Prompt 工程**：`backend/config/courses/python/prompts.yaml` 集中管理各智能体提示词，按职责分别设计：
  - 内容生成：场景引入开头 + 口语化学长风格 + 生活化代码示例（禁用 foo/bar 等无意义命名）+ 易错点「为什么容易错」
  - 测验出题：干扰项用常见误解设计，解析须说清「正确答案为什么对 + 典型错误选项错在哪」
  - 学习辅导：引导式教学 —— 先启发性提问再给答案，代码错误先让学生猜哪行，结尾留延伸思考题
- **稳定性控制**：超时重试、流式异常兜底、输出长度上限，避免长内容生成时前端等待失控

### 5.2 RAG 检索增强

```
课程知识库（教材 PPT 11 章切片 + 习题 206 条 + 学习路径 55 条）
   → 离线向量化（TF-IDF + SVD 降维至 256 维，无需联网调用 Embedding API）
   → FAISS 索引（学习路径索引 + 习题索引）
   → 学生提问时检索 Top-K 相关片段
   → 片段 + 问题 + 学习者画像 一起拼进提示词
   → 大模型生成有据可依的回答
```

**为什么用离线 TF-IDF + SVD 而不是调用 Embedding API？**
成本为零、无网络依赖、毫秒级检索，对课程知识库这种**领域封闭、术语集中**的场景足够准确 —— 学生问的「切片」「推导式」在向量空间里能被稳定区分。这也让评审无需配置额外的 Embedding 密钥即可复现。

### 5.3 AI 安全与可控

- **输入侧**：`app/core/safety.py` 做敏感内容过滤
- **输出侧**：RAG 约束回答范围，避免大模型幻觉编造语法；系统提示词明确「不确定就说不确定」
- **数据侧**：API 密钥全部走环境变量，仓库不含任何真实密钥（见 [八、快速开始](#八快速开始)）
- **失败兜底**：大模型不可用时有降级提示，不会白屏或静默卡死

### 5.4 流式交互与状态可视化

- 后端 SSE 逐字推送，前端 `EventSource` 增量渲染，Markdown 边生成边解析
- 三阶段思考状态（分析学习画像 → 检索课程知识库 → 生成专属学习内容）用 ✓ / 转圈 / 待办三种状态呈现，超过 30 秒追加「内容较长请稍候」，把「黑盒等待」变成「看得见的进度」

## 六、技术创新点

### 技术创新

1. **多智能体协同 + 动态画像驱动的闭环架构**
   多个智能体不是并行独立工作，而是围绕同一份画像接力：错题 → 画像 → 路径 → 讲解，形成自我强化的学习闭环。这是本作品与「单 Agent 聊天机器人」的核心区别。

2. **分层意图识别路由**
   强关键词 → Embedding 语义 → 弱关键词 → 默认兜底，四级降级策略兼顾准确率与响应速度，避免单靠 LLM 意图分类带来的延迟与不稳定。

3. **零成本离线 RAG**
   TF-IDF + SVD + FAISS 的纯本地检索链路，无需 Embedding API、无需联网，克隆仓库即可复现检索效果。

4. **画像驱动的自适应出题**
   出题难度与知识点并非固定，而是读取画像中的水平与易错主题动态决定。

### 应用创新

5. **错题驱动的复习闭环**
   错题不只「记下来」，而是自动反哺画像、插入学习路径、影响后续讲解 —— 学生无需任何手动操作，系统自己完成闭环。

6. **结构化学习画像（EAV 模型）**
   画像不是一段自然语言描述，而是可查询、可增量更新的结构化数据，支撑路径规划、出题、讲解等多处消费。

7. **轻量透明的学习报告**
   汇总真实行为数据后由大模型生成分析，既可缓存也支持重新生成，让「学了多久、弱在哪」一目了然。

## 七、技术栈

| 层次 | 技术选型 | 选型理由 |
|---|---|---|
| 前端框架 | Vue 3（Composition API）+ Vite | 组件化开发，HMR 提升迭代效率，构建产物轻量 |
| 前端状态 | Pinia | 轻量、TypeScript 友好，聊天/路径/画像三个 store 职责清晰 |
| 路由 | Vue Router | 按需加载，首屏体积可控 |
| 流式通信 | 原生 EventSource（SSE） | 比 WebSocket 更轻，单向流式场景足够，天然支持断线重连 |
| 后端框架 | FastAPI + Uvicorn | 原生支持 SSE 与异步，自动生成 OpenAPI 文档 |
| 数据库 | MySQL 8.0 | 画像/路径/错题为结构化数据，需要事务与精确查询 |
| 向量检索 | FAISS + scikit-learn | 本地化、零成本、检索延迟低 |
| 大模型 | 讯飞星火 4.0Ultra | 中文教育场景表现稳定，OpenAI 兼容接口便于替换 |
| 知识库 | 教材 PPT + 习题库 + 路径库 | 自主整理，内容可控、无版权风险 |

## 八、快速开始

### 8.0 前置条件

- Python 3.11+
- Node.js 18+
- MySQL 8.0（本机已安装并启动）

> 提供 Windows 一键脚本：双击项目根目录的「**环境安装.bat**」自动完成虚拟环境创建与依赖安装。

### 8.1 配置环境变量（必做）

仓库**不包含任何真实密钥**，只提供模板。复制模板后填入自己的值：

```bash
cd backend
# Windows
copy .env.example .env
# macOS / Linux
cp .env.example .env
```

然后编辑 `backend/.env`，填入讯飞开放平台（<https://console.xfyun.cn>）的密钥：

| 变量名 | 说明 | 是否必填 |
|---|---|---|
| `SPARK_APP_ID` | 讯飞应用 AppID | 必填 |
| `SPARK_API_KEY` | 讯飞 API Key | 必填 |
| `SPARK_API_SECRET` | 讯飞 API Secret | 必填 |
| `SPARK_API_BASE` | 接口地址，默认 `https://spark-api-open.xf-yun.com/v1` | 有默认值 |
| `SPARK_MODEL` | 模型名，需与所领试用包一致（如 `4.0Ultra`） | 有默认值 |
| `SPARK_BEARER_TOKEN` | 星辰 MaaS 平台专用，用不到可留空 | 可选 |
| `SPARK_THINKING` | 是否开启思考模式，默认 `false` | 有默认值 |
| `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DATABASE` | MySQL 连接信息，库会在启动时自动创建 | 按实际修改 |

> ⚠️ **重要**：凡是有默认值的键，若不需要修改请**整行删除**，不要写成 `KEY=`。dotenv 读到空值也算「已设置」，会把默认值覆盖为空字符串导致启动失败。
>
> ⚠️ `.env` 已在 `.gitignore` 中，请勿提交到 Git。

### 8.2 启动后端

```bash
cd backend
python -m venv .venv                # 首次运行
.venv\Scripts\activate              # Windows
# source .venv/bin/activate         # macOS / Linux
pip install -r requirements.txt
uvicorn main:app --host 127.0.0.1 --port 8000
```

后端启动时自动创建 `agents` 数据库与全部数据表，无需手动建库。
接口文档：<http://localhost:8000/docs>

> Windows 用户也可直接双击项目根目录的「**启动项目.bat**」，会同时拉起前后端。

### 8.3 启动前端

```bash
cd frontend
npm install
npm run dev
```

打开 <http://localhost:5173>。Vite 已配置 `/api` 代理到 8000 端口。

### 8.4 重新构建向量索引（改动知识库后）

```bash
cd backend
.venv\Scripts\python -m app.rag.indexer
```

## 十一、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 启动报 `Unknown database 'agents'` | MySQL 未启动或密码不对 | 启动 MySQL 服务；检查 `backend/.env` 里的 `MYSQL_PASSWORD` |
| 8000 端口被占用 | 之前的服务未关闭 | 换端口，同时修改 `frontend/vite.config.js` 里的 proxy target |
| 生成内容报「星火密钥无效」/ `AppIdNoAuthError` | `.env` 未创建或密钥填错 | 复制 `.env.example` 为 `.env` 并填入正确密钥，同时在讯飞控制台为应用**领取对应模型的试用包** |
| 启动报 `Invalid URL '/chat/completions'` | `.env` 里某个有默认值的键被写成了空值 | 整行删除该键（不要留 `KEY=`） |
| 有 `.venv` 缺失报错 | 未创建虚拟环境 | 先执行 8.2 的 venv 创建步骤，或双击「环境安装.bat」 |
| 点「开始学习」后长时间无内容 | 完整讲义需 30~60 秒才出第一个字 | 属正常现象，界面会显示实时用时；超过 2 分钟检查后端控制台 |
| 启动有 `InconsistentVersionWarning` | 离线模型用旧版 sklearn 训练 | 不影响运行；要求严格时可安装对应版本 sklearn |
